## 3. القرار المطلوب وترتيب FC20-05

[قرار الأدوار المسجل](https://github.com/alphasigma13579-lang/ASIE/pull/172#issuecomment-5858245957) يثبت أن المالك صاحب الاعتماد النهائي، وCodex مستشاره في البرنامج والمعمارية والأمن وAI. المسميات الوظيفية مسؤوليات مراجعة، ولا تفترض أربعة موظفين. مراجعة روبوت أو CI لا تحل محل قرار المالك أو الدليل الفني.

**توصية Codex للمراجعة:** تقديم إصلاح التوجيه المحدود على استكمال بقية الرحلة، وفق فصل النطاق المتفق عليه، مع إبقاء عمل FC20-05 وأدلته والمتبقي منه محفوظًا. لا يبدأ التنفيذ بمجرد قبول هذه التوصية.

قرار الترتيب اللاحق يختار أحد البديلين ويحدد النسخة والسبب:
1. إكمال المتبقي المثبت من FC20-05 وفق عقد إغلاقها، ثم نقل التنفيذ إلى التوجيه.
2. تقديم التوجيه بإعادة ترتيب حاكمة مستقلة: تثبيت نقطة توقف FC20-05، أعمالها المدمجة والمتبقية ونقطة استئنافها، ثم اعتماد تمثيل ترتيب يفرض تنفيذًا واحدًا عبر الحزم والشرائح معًا قبل بدء التوجيه.

لا تعلن FC20-05 COMPLETE صوريًا، ولا تختلق حالة PAUSED أو تعيدها OPEN لإرضاء الاختبار. التمثيل الآلي المناسب لإعادة الترتيب **لم يُصمم أو يُعتمد بهذه الحزمة**؛ يراجع في PR أهلية مستقل. حتى ذلك الحين تبقى FC20-05 وحالات الحزم الحالية كما هي. إعداد الوثائق لا يبدأ تنفيذ شريحة تشغيلية ثانية.

يبقى `FC20-12.depends_on = FC20-08/09/11` شرطًا لإغلاق الأب وأعمال المجلس/اللقطة. دخول التوجيه قبل إغلاقها الكامل لا يصبح نافذًا إلا بعد قبول انتقال أهلية مضبوط واستيفاء ضوابطه؛ لا تُستنتج الأهلية من ترتيب مقترح أو من هذه الوثيقة.

## 4. التصميم المحدود الذي يُعرض للاعتماد

هذا تلخيص مشتق من ACR، لا تسجيل لعقود أو موافقة جديدة:

```text
HTTP مخول
→ Workflow القائم
→ ModuleRuntime القائم → Bus/Socket admission
→ handler المسجل المختص → أثر مأذون
→ مخرج آمن / مرشح للمراجعة
```

- HTTP ينقل نية محدودة؛ tenant/project من الجلسة والمشروع. لا provider client أو كتابة سياق مباشرة أو module/socket/namespace يحدده المتصفح.
- مالك كتابة السياق خلف القبول؛ state/hash من الخادم، وإصدار وإيصال وبصمة، transaction/CAS/idempotency. لا حلقة handler → Workflow للأمر نفسه.
- السوق والموقع خلف أوامر مسجلة بعد سلطاتها، بالمصادر المقبولة والموقع المؤكد. لا زحف جديد أو تخزين Places في المعرفة العامة.
- التفسير عبر `socket.ai.integration` الوحيد وAIIntegrationShell القائم. request v2 وoverlay v1 تحت ACR-AIA-09 مستقل؛ result v1 محفوظ. لا سوكت أو Runtime أو Gateway AI آخر، ولا run/snapshot وهميان لإرضاء v1.
- تفاصيل schemas وربط النسخ تحت الطلبات المالكة؛ أسماؤها المقترحة في ACR ليست عقودًا مسجلة الآن. عند غياب عقد/ضابط لازم، يتوقف الأمر قبل أثره؛ لا fallback إلى الخدمة المباشرة.
- Project Run v1 وFinance وDecision Council وSnapshot لا تضاف إليها هذه الطبقة. التفسير لا يملك الأرقام المالية أو قرار التمويل. سند يبقى تنقلًا محليًا إلى المدخل ومسار العودة.
- العربية ورسائل التعافي وإخفاء IDs/hash/engine/contract للعميل وفق EKB-08. لا يتحول هذا الملخص إلى تصريح إعادة تصميم الواجهة.

## 8. نقاط القرار والمراجعة

1. مراجعة هذه الحزمة على رأس PR الخاص بها، ثم عرض ترتيب التنفيذ وحدود التصميم والمخاطر على المالك. دمج مقترح لا يغير الحالة إلى APPROVED.
2. أي قبول يسجل صراحة: القرار، صاحب الاعتماد، وقت UTC، نسخة/رأس الوثيقة، السبب، النطاق، الشروط، الأدلة الناقصة، وما لم يسمح به. لا توضع توقيعات أو PASS نيابة عن المالك.
3. إعداد انتقال الأهلية وطلبات الاختصاص المالكة بعد تفويض محدد؛ مراجعتها على الرأس نفسه. لا يُعدل السجل الحالي كاختصار قبل ذلك.
4. لا يبدأ كود مجمد إلا بعد انتقال أهلية معتمد وفعّال واستيفاء ضوابط الدخول وACR/التجميد. عند تعارض أو ضابط مفقود يتوقف الجزء المعتمد عليه وتُعرض الخطوة المطلوبة؛ لا قفز آلي لهدف آخر.
5. التشغيل والنشر يبقيان تحت FC20-16 وPROGRAM-CLOSE-10 وقرار الإصدار؛ لا يمنحهما نجاح البناء أو موافقة ترتيب. مفاتيح Hostinger وCanary ودعوات البيتا خارج هذا الطلب.

مراجعة الاتساق الذاتية ليست مراجعة مستقلة. تُحفظ نتيجة المراجع الفعلية منفصلة على رأسها، وأي حجب حصة لا يعد نجاحًا؛ لا يعاد طلب مراجعة جارية أو محجوبة قبل موعد إتاحتها.

## 9. قبول إعداد الحزمة ونقطة الاستئناف

قبول هذه الشريحة التوثيقية: الثلاثة ملفات فقط، روابط ومواضع مصادر قابلة للوصول على الرأس المحدد، تمييز المقترح من المنفذ، لا تغيير للكود/السجل/التجميد، وPR مع فرق ودليل تحقق وحدود مراجعة ظاهرة. اكتمال إعدادها لا يعني اكتمال بوابات الدخول أو الإصلاح أو اعتماد البناء.

نقطة التوقف الآمنة: تسليم PR للمراجعة وقرار المالك، بلا دمج. التالي: مراجعة الحزمة وحسم قرار الترتيب وحدود الاعتماد، ثم تفويض مرحلة حاكمة محددة لا كود تشغيل تلقائيًا.

بعد الإصلاح المحدود تستأنف [خطة بيتا المالك والإدارة المستقلة](ASIE-BETA-EXECUTION-MASTER-PLAN-2026-09-09.md): المتبقي المثبت ورسائل الفشل، أدلة التخزين، /admin مستقل، النشاط والعربية وسند، ثم تجهيز واختبار المالك بتفويضه. الدعوات مغلقة. الأسواق الأربعة/اقتراح المشاريع/محرك استدلال عام أعمال لاحقة محفوظة، لا يبدأ أي منها هنا.
