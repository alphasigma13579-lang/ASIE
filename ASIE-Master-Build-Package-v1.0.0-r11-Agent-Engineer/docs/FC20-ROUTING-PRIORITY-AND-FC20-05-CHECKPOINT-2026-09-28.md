## القرار وأثره المحدود

يُقدَّم إصلاح التوجيه المحدود على استكمال المعرفة الاقتصادية العامة؛ السبب معالجة منافذ التجاوز المثبتة قبل توسيع القدرات. تُحفظ FC20-05 بأعمالها وأدلتها ومتطلباتها دون COMPLETE صوري أو تغييرها إلى OPEN/PAUSED.

بديل إكمال FC20-05 أولًا يبقى خيار رجوع بقرار مالك لاحق؛ الالتفاف أو Runtime/Bus/AI socket موازٍ ليس خيارًا. لا يفسر الترتيب كتخفيض لاعتماديات أو شروط سلامة.

التمثيل المقترح في هذا PR هو `execution_sequence` داخل سجل البرنامج نفسه، لا مصدر حالة موازٍ:
- `priority_target`: FC20-12/routing_repair؛ أولوية، وليست تصريحًا.
- `held_packages`: FC20-05 فقط، مع checkpoint محدد وسبب وشرط استئناف.
- `active_target = null`: لا تنفيذ تشغيلي مختار الآن. ليست علامة على إلغاء process حي؛ لم يفحص هذا الطلب عمليات Hostinger.
- `max_active_executions = 1`؛ العداد يجمع IN_PROGRESS للحزم غير المحجوزة **وكل الشرائح**، بما فيها الشرائح داخل حزمة محجوزة. لا يجوز إخفاء شريحة تنفيذ داخل hold.
- حالة FC20-05 المسجلة IN_PROGRESS تعني تقدمًا غير مغلق، مع hold تنفيذ صريح في هذا السجل؛ لا تُفسر وحدها كتنفيذ حالي. جميع الحالات والاعتماديات والأدلة الأصلية محفوظة.
- v1 هنا يقبل خانة فارغة فقط ويمنع كل ادعاء تنفيذ غير مسجل. فتح خانة لشريحة أو استئناف الحزمة يحتاج تغييرًا حاكمًا لاحقًا مع دليل واعتماد الرأس، لا تعبئة ID أو boolean.
- `validate_execution_sequence` و`validate_routing_registration` حارسا اتساق CI فقط، وليسا runtime lock أو خدمة تفويض أو تحقق توقيع. حدود التطبيق الفعلية لا تتغير.

لا تنفيذ للتوجيه الآن: التسجيل يبقى REGISTERED_BLOCKED / REGISTRATION_ONLY، وكل الضوابط PENDING، وأعلام التنفيذ/الشبكة/المزودات/النشر false. تبقى اعتماديات 08/09/11 لإغلاق الأب، وFC20-16 محجوبة؛ لا إغلاق أب أو إصدار من الأولوية.
