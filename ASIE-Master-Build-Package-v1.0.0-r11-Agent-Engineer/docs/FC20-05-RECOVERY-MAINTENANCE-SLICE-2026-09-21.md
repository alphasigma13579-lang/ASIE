# F05-01C — الاستيراد والنسخ والاستعادة المستقلة
التاريخ: 2026-09-21. الحالة: التنفيذ والاختبارات المعزولة موجودة في #167؛ أدلة قبول الرأس النهائي والمراجعة قيد الاستكمال. ليست تصريح ترحيل أو تشغيل.
## المرجع والاعتماد

- [نطاق المعرفة](EKB/domains/Public-Economic-Knowledge.md) و[ACR](ACR-FC20-05-PUBLIC-ECONOMIC-KNOWLEDGE-2026-08-23.md).

## النتيجة المطلوبة
استيراد JSON موثوق إلى مخزن جديد، ونسخة مستقلة قابلة للتحقق والاستعادة، ومقارنة دلالية تشمل corpus وjournal، ورفض هوية الطلب القديمة بعد الاستعادة، وإثبات إعادة بناء الفهرس بمزود معزول.
## التنفيذ
1. محول صيانة مستقل يعيد استخدام قفل التخزين وحماية المسارات والتحقق من النطاق قبل I/O. لا endpoint أو قراءة أسرار أو عميل مزود حي.
2. استيراد صريح: حدود حجم/عمق، schema، مصادر ومعرفات ونسخ وحالات وmetadata، رفض بيانات المشروع والتلف والتعارض؛ بصمة واستيراد ذري إلى وجهة جديدة. إعادة نفس الاستيراد لا تكرر البيانات، ومدخل مختلف إلى وجهة مستخدمة يرفض. الأصل لا يعدل ولا يحذف.
3. نسخة عبر SQLite backup API تحت القفل نفسه؛ تحقق integrity وforeign keys والمخطط والسجل، وبصمة وmanifest ومقارنة دلالية. لا نسخ WAL منفرد ولا اعتبار ملف جزئي نسخة صالحة.
4. استعادة إلى وجهة مستقلة لا تستبدل مخزنًا قائمًا، تحقق وقراءة مستقلة قبل قبولها. إعداد الكتابة ينشئ restore_epoch جديدًا وحدثًا موثقًا ويمنع طلبات العصر السابق قبل أي أثر، مع إبقاء التاريخ.
5. لا تفتح بوابة الفهرس المستعاد لمجرد نجاح الاستعادة؛ إعادة البناء والتحقق الصريحان بمحول اختبار فقط، وتبقى النتائج غير الموثوقة محجوبة. لا delete_all ولا حذف معرفات مجهولة أو افتراض تسوية طلب حي.
## الملفات المتوقعة
- محول صيانة واختباراته المنفصلة تحت backend/ وtests/.
- public_corpus_store.py وpublic_corpus_files.py عند ضرورة إضافة نقاط امتداد متحققة، دون تخفيض حمايات B.
- public_knowledge_lifecycle.py وpublic_knowledge.py فقط عند حاجة تحقق أو استعادة مرتبطة.
- workflow التخزين لتغطية اختبارات C، وهذه الخطة ومدخل EKB.
- deploy/backup.sh مرتبط تشغيليًا لكنه خارج التفعيل في هذه الشريحة.

## الحدود ونقطة التوقف
لا Finance أو Snapshot أو AAS أو Decision Council؛ لا بيانات مالك أو ترحيل تلقائي أو نشر أو شبكة أو مزود حي أو تعديل صلاحيات أو دعوات. لا ادعاء RPO/RTO أو نسخة احتياطية حية. تبقى منظومة المصدر الأصلية دون تبديل؛ فشل الوجهة لا يبرر حذف الأصل.
التسليم PR مستقل غير مدموج مع سجل قبول ومخاطر باقية. مراجعة CodeRabbit وCopilot أو بديل موثوق عند التعذر، دون تغيير الرأس أثناء مراجعة معلقة. الاختبارات تجمع لكل دفعة متماسكة؛ لا إعادة نجاح دون سبب.
التقدير الأولي 25–45 ألف توكن للقياس فقط، لا سقف. التقرير الفعلي عند إغلاق الهدف.

## قرار التنفيذ في C
- يحتفظ المخزن العادي بإصدار v2. تستخدم وجهات الاستيراد/الاستعادة الجديدة فقط إصدار v3 مع imports وحالة صيانة وأحداث استعادة مستقلة؛ لا ترقية تلقائية لقاعدة قائمة.
- تحفظ المقارنة الدلالية هوية صفوف العمليات والخطوات وJSON المفكوك، وليس الأعداد فقط. يبقى corpus وسجله التاريخي دون إعادة كتابة عند الاستعادة؛ epoch وحالة الصيانة يسجلان منفصلين.
- إعادة البناء تتطلب محولًا خادميًا محقونًا يثبت توقف جميع الكتابات القديمة، وتسوية كل محاولة مسجلة، وتطابق الفهرس كاملًا. لا يكفي تطابق عينة من المعرفات. لا يوجد محول حي لهذا البروتوكول في هذه الشريحة.
- الاختبارات تقرأ JSON باسم المسار القديم الفعلي public_knowledge_corpus.json دون إعادة تسميته أو تعديل الأصل.
- توسعة فروع CI تشمل قاعدة PR التابعة لـ#166 لكي تُختبر C دون دمج سابقها. مهلة Windows للتخزين 45 دقيقة لأن B وحدها استغرقت 19 دقيقة، وتضاف اختبارات C؛ لا تعد المهلة دليل نجاح.

## حدود الثقة وأدلة الفشل
| الأصل/المسار | التهديد | الضابط والدليل |
|---|---|---|
| JSON قديم → قاعدة جديدة | تلف أو مشاركة هوية أو بيانات مشروع | تحقق جميع النسخ والحقول قبل إنشاء قاعدة الوجهة؛ اختبارات ملف مكرر/جزئي وmetadata والتصنيف |
| قاعدة → نسخة مستقلة | نسخ غير متسق أو سجل يتيم | backup API تحت القفل، integrity/FK/schema/journal، مقارنة دلالية وبصمة وفتح قراءة فقط |
| نسخة → استعادة | انقطاع بعد النسخ وقبل تغيير epoch | علامة تثبيت دائمة قبل النسخ؛ الجلسة العادية ونسخ المصدر يرفضان الوجهة حتى ختم التحقق المرتبط بالـepoch |
| صيانة المنصة | محاولة مستأجر أو استبدال مسار | TrustedProviderScope قبل I/O، الأقفال وACL/no-follow والإنشاء الحصري؛ اختبارات رفض دون فتح ملف |
| استعادة سجل غير نهائي | حظر دائم أو تسوية وهمية | reconcile صريح للسابق بعد quiescence/settlement ثم تطابق namespace كامل؛ compensated يحفظ الهوية القديمة ولا يفتح بوابة الصيانة وحده |
| إعادة بناء الفهرس | طلب متأخر أو حذف معرفة غير معروفة | تثبيت هوية الصيانة قبل الأثر، سجل كل محاولة، لا حذف إلا IDs المعروفة، proof كامل قبل ready |
| إخفاق مزود | تسريب استثناء إلى ملخص أو journal | حالة آمنة ثابتة؛ اختبار علامة حساسة في استثناء معزول |

الأصول عامة ولكن سلامة حالتها وسجلها حساسة تشغيليًا. المالك هو عبء public-knowledge-sync، وليس المستأجر. لا سياسة احتفاظ أو حذف تلقائي جديدة، ولا RPO/RTO مخترعان. كل التدفقات متزامنة تحت قفل محلي محدود الانتظار؛ لا retry تلقائي. الفهرس مشتق وSQLite الحقيقة. التحقق من البيئة الحية وflush/توقف الطلبات الخارجية مسؤولية خطوة التشغيل اللاحقة، ولا تثبتها هذه الاختبارات المعزولة. حالة دليل الأمن/التشغيل تظل غير مكتملة حتى اجتياز اختبارات ومراجعات الرأس النهائي، ولا يعني اجتيازها تصريح نشر.

المراجعة الأولى على 20936aa أظهرت نقص resolver في إعداد اختبار فقط، وتعارض deleted_at مع مصدر نشط، وانسداد تعافي عملية موروثة. الدفعة التالية تعالجها وتضيف اختبار نافذة انقطاع النسخ المكتشفة بالتدقيق المستقل؛ لا تخفف الصلاحيات ولا ترفض النسخ ذات السجل غير النهائي كبديل عن التعافي.

مراجعة الرأس 3a569491 كشفت أن بصمة المقبض المفتوح وحدها لا تكشف استبدال مسار المصدر ذريًا. يعاد التحقق من هوية المسار والبصمة قبل ختم الوجهة وقبل نجاح الاستيراد، بما فيه مسار التكرار. اختبار متزامن يستبدل الملف أو يغير محتواه أثناء الاستيراد يثبت الرفض، أو منع نظام Windows للتغيير نفسه. يظل تشغيل كاتب JSON القديم متوقفًا أثناء إجراء الاستيراد التشغيلي؛ الفحوص لا تمنح قفلًا لكاتب قديم غير مشارك في بروتوكول SQLite.

حماية ملف النسخة: تنشأ علامة backup غير قابلة للتشغيل قبل إنشاء قاعدة النسخة، وتبقى بعد نجاح النسخ أو انقطاعه. الجلسة العادية ترفضها قبل فتح SQLite أو تحويل WAL. قارئ الصيانة فقط يتحقق من العلامة والمخطط والبصمات؛ الاستعادة الصريحة تنتج وجهة جديدة بعصر جديد وبوابة إعادة بناء مغلقة. اختبارات النسخة المكتملة والمنقطعة تثبت منع التشغيل وعدم تعديل الأصل.
