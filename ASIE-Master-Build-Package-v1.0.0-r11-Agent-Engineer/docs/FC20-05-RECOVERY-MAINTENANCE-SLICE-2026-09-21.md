# F05-01C — الاستيراد والنسخ والاستعادة المستقلة

## النتيجة المطلوبة
استيراد JSON موثوق إلى مخزن جديد، ونسخة مستقلة قابلة للتحقق والاستعادة، ومقارنة دلالية تشمل corpus وjournal، ورفض هوية الطلب القديمة بعد الاستعادة، وإثبات إعادة بناء الفهرس بمزود معزول.
## التنفيذ
1. محول صيانة مستقل يعيد استخدام قفل التخزين وحماية المسارات والتحقق من النطاق قبل I/O. لا endpoint أو قراءة أسرار أو عميل مزود حي.
2. استيراد صريح: حدود حجم/عمق، schema، مصادر ومعرفات ونسخ وحالات وmetadata، رفض بيانات المشروع والتلف والتعارض؛ بصمة واستيراد ذري إلى وجهة جديدة. إعادة نفس الاستيراد لا تكرر البيانات، ومدخل مختلف إلى وجهة مستخدمة يرفض. الأصل لا يعدل ولا يحذف.
3. نسخة عبر SQLite backup API تحت القفل نفسه؛ تحقق integrity وforeign keys والمخطط والسجل، وبصمة وmanifest ومقارنة دلالية. لا نسخ WAL منفرد ولا اعتبار ملف جزئي نسخة صالحة.
4. استعادة إلى وجهة مستقلة لا تستبدل مخزنًا قائمًا، تحقق وقراءة مستقلة قبل قبولها. إعداد الكتابة ينشئ restore_epoch جديدًا وحدثًا موثقًا ويمنع طلبات العصر السابق قبل أي أثر، مع إبقاء التاريخ.
5. لا تفتح بوابة الفهرس المستعاد لمجرد نجاح الاستعادة؛ إعادة البناء والتحقق الصريحان بمحول اختبار فقط، وتبقى النتائج غير الموثوقة محجوبة. لا delete_all ولا حذف معرفات مجهولة أو افتراض تسوية طلب حي.
## الملفات المتوقعة
- محول صيانة واختباراته المنفصلة تحت backend/ وtests/.
- public_corpus_store.py وpublic_corpus_files.py عند ضرورة إضافة نقاط امتداد متحققة، دون تخفيض حمايات B.
- public_knowledge_lifecycle.py وpublic_knowledge.py فقط عند حاجة تحقق أو استعادة مرتبطة.
- workflow التخزين لتغطية اختبارات C، وهذه الخطة ومدخل EKB.
- deploy/backup.sh مرتبط تشغيليًا لكنه خارج التفعيل في هذه الشريحة.
## بوابات القبول

|---|---|
| عدم فقد الأصل | بصمة الأصل قبل/بعد النجاح والفشل |
| الاستيراد | مقارنة السجلات والتاريخ والتدقيق؛ التكرار/اختلاف المدخل/التلف مرفوض أو idempotent حسب العقد |
| النسخة | integrity=ok وforeign_key_check فارغ؛ رفض operation_steps يتيم ولو نجح integrity |
| الاستعادة | قاعدة مستقلة كاملة دلاليًا؛ تلف manifest/البصمة/المخطط يرفض |
| الهوية | عملية بعد النسخة ثم استعادة الأقدم وإعادة المفتاح/epoch القديم: صفر أثر أو تدقيق جديد |
| التعافي والفهرس | بقاء الحظر حتى إثبات الاتساق؛ النشط فقط يعاد بناؤه؛ لا حذف غير معروف |
| الأمن | رفض غير المخول قبل I/O، صلاحيات/روابط/مسارات آمنة، عدم كشف أسرار أو سياق مستأجر |
| الانقطاع والتزامن | لا اعتماد وجهة جزئية؛ لا كتابة متعارضة مع lifecycle؛ أدلة Linux وWindows المناسبة |
| التسليم | فرق محدود، فحوص مناسبة ومراجعات exact-head، لا ملفات مجمدة |
## الحدود ونقطة التوقف
لا Finance أو Snapshot أو AAS أو Decision Council؛ لا بيانات مالك أو ترحيل تلقائي أو نشر أو شبكة أو مزود حي أو تعديل صلاحيات أو دعوات. لا ادعاء RPO/RTO أو نسخة احتياطية حية. تبقى منظومة المصدر الأصلية دون تبديل؛ فشل الوجهة لا يبرر حذف الأصل.
التسليم PR مستقل غير مدموج مع سجل قبول ومخاطر باقية. مراجعة CodeRabbit وCopilot أو بديل موثوق عند التعذر، دون تغيير الرأس أثناء مراجعة معلقة. الاختبارات تجمع لكل دفعة متماسكة؛ لا إعادة نجاح دون سبب.
