# F05-01B — خطة ربط دورة المعرفة والتعافي
المرجع: [التصميم المعتمد](FC20-05-TRANSACTIONAL-CORPUS-DESIGN-2026-09-09.md). الأساس الرسمي: 6aa5a514b0827a1ef0998eb539935df0eacc19c1.
## النطاق والنتيجة
ربط run/delete_source/restore_source/reindex بالمحول عبر خدمة داخلية صريحة، وتثبيت هوية المدخل والنتيجة قبل إعادة الطلب، وخطة آثار وتعويض دائمة، وبوابة قراءة ترتبط بrevision والنسخة النشطة.
## خطوات التنفيذ
1. إصدار مخطط B مع نتيجة نهائية وتعويض مكتمل؛ ترقية A صريحة متحققة، لا تلقائية. حفظ التاريخ ورفض التلف.
2. فصل تحميل/حفظ corpus في المزامن القائم خلف أساليب قابلة للاستبدال، وإعادة استخدام القبول والتحضير الموجودين دون نسخ خوارزمية المصادر.
3. خدمة معاملات: قفل كامل، lookup قبل الجلب، تحضير في الذاكرة بلا فهرسة، journal قبل أول أثر، commit نهائي واحد. فشل الفهرسة يرجع الدفعة كاملة للإسقاط السابق بدل السماح بتحديث محلي غير مثبت؛ فشل جلب مصدر يبقى متوافقًا مع ملخص partial القائم.
4. التعافي لا يرفع الحظر دون تحقق خادمي من انتهاء الطلبات الملتبسة والتحقق من الإسقاط؛ غياب هذا الدليل يعني recovery_required بلا إعادة محاولة عادية. لا انتظار زمني مفترض ولا delete_all.
5. قراءة tenant موثوق، فحص الحالة قبل/بعد الاسترجاع وتطابق الحقول والهوية مع corpus؛ لا حفظ query أو سياق المشروع.
## حدود
المصنع الحالي لا يُفعّل المسار الجديد تلقائيًا. خدمة B داخلية قابلة للحقن ومختبرة بمزودات معزولة فقط. لا تغيير namespace أو صلاحيات أو خدمات حية أو أسرار أو ملفات Finance/Snapshot/AAS/Decision Council. يبقى انتقال الكاتب القديم وإعداد خدمة التسوية من متطلبات الانتقال التشغيلي؛ لا مزج كاتبين على بيانات واحدة.
الاستيراد والنسخ/استعادة النسخ في C. ترقية قواعد A في اختبارات مؤقتة فقط، ولا قراءة أو ترقية بيانات المالك.
## بوابات ونقطة توقف
اختبارات scope قبل I/O، تكرار/اختلاف المدخل/epoch، tombstones، الفشل قبل/بعد الآثار وcommit، فشل التعويض، الانقطاع وإعادة فتح الخدمة، منع القراءة أثناء drift، سر في الاستثناء، وعدم توسعة المصادر. اختبارات A القائمة وعدم تراجع المزامن، ثم CI ومراجعات exact-head.
التسليم PR مفتوح مع نتائج واختبارات وحدود واضحة؛ لا دمج أو نشر. تقدير 20–40 ألف توكن للقياس فقط.
