## فجوات مثبتة وحدود الاستنتاج

1. **التصنيف المخصص:** [sector_intelligence.py](https://github.com/alphasigma13579-lang/ASIE/blob/70331cdbd24daf22bfd9ab4a9c5252d39eccb661/ASIE-Master-Build-Package-v1.0.0-r11-Agent-Engineer/backend/sector_intelligence.py#L152) يستبدل subsector غير المدرج بأول subsector (163–165)، بينما الواجهة تسمح بالتخصيص. خطر فقد دقة التصنيف مثبت ساكنًا؛ لم نختبر أثره الحي ولم نصلحه هنا.
2. **قائمة المصادر ليست قائمة تفعيل:** الأسواق الأربع مطلوبة الآن في المرجع؛ غيابها عن السجل العام المفتوح لا يعالج بإقحام كتالوج تجاري فيه. لكل مسار سجل وسياسة مالكة.
3. **المعرفة ليست مخزنًا واحدًا لكل شيء:** المعرفة العامة المقبولة منفصلة عن سياق المشروع وعروض المستخدم وبيانات Places.
4. **أسس التكلفة لا تثبت خط بحث أسعار كاملًا:** لا يوجد في الدليل المفحوص ما يثبت موصلات الأسواق الأربع مع المطابقة والشحن والضريبة والتجهيز واعتماد البنود عبر الرحلة كاملة.
5. **واجهة جزئية لا تنفي وجود مسار آخر:** بطاقات «قريبًا» في CommandCenter لا تعني عدم وجود LiveMarketMap؛ والمكوّن المحلي القديم market_context لا ينفي مسار intelligence/market-context الأحدث.
6. **اقتراح بديل يحتاج معيارًا:** ملاءمة رأس المال والمهارات والموقع والطلب والتنافس والمخاطر؛ لا يكفي خبر نمو أو سعر رخيص أو غياب نتائج خريطة للقول إن مشروعًا أفضل.

## ترتيب التطوير المقترح بعد مراجعة المالك

1. حسم التصنيف الوطني والنشاط المخصص وحفظ اختيار المستخدم.
2. سجل عمليات المصادر والتراخيص والمستهلكين، دون خلط التجاري بالاقتصاد العام.
3. تجربة دليل سعر واحدة مأذونة من مواصفات البند إلى مراجعة الافتراض، ثم توسيع الموصلات تدريجيًا.
4. ربط نتائج الموقع والسوق والأسعار بسند والإرشاد مع حدود الثقة والعودة.
5. اختبار تحسين فكرة أو مقارنة بديل على أدلة متكافئة، والتقارير المعتمدة فقط.

هذه مراحل مقترحة لا أهداف تنفيذ مفعّلة بهذه الوثيقة. أعمال التخزين ورسائل الفشل السابقة لا تسقط ولا تعد مكتملة.
