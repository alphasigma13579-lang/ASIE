## 5. من أين وإلى أين وحدود الملكية

`HTTP المخول → Workflow القائم → ModuleRuntime القائم → System Bus / Bus Controller / Socket validation → handler المسجل المختص → أثر مأذون → مخرج آمن`.

هذا وصف نقاط القبول لا إعادة ترتيب للـpipeline؛ تظل طريقة القبول والتنفيذ الفعلية كما يحكمها AAS. API ينقل النية، لا يختار socket/module/tenant ولا ينشئ عميل مزود ولا يكتب السياق مباشرة. handler السياق هو مالك الكتابة؛ لا يستدعي Workflow ثانيةً على الأمر نفسه. لا تنشأ run/snapshot IDs وهمية لتلبية عقد v1.

الذكاء عبر `socket.ai.integration` الوحيد وAIIntegrationShell القائم؛ request v2/overlay v1 تحت ACR-AIA-09، وresult v1 محفوظ؛ لا result v2 أو AI Gateway جديد. قبول Registry لا يعوض التفويض وإعادة فحص السياسة داخل مالك الأثر. سند يبقى تنقلًا محليًا.

## 7. بوابات الاختبار والأدلة

هذه متطلبات اختبارات مستقبلية، وليست نتائج PASS.

| المعرف | الاختبار المطلوب | معيار الفشل/النجاح |
|---|---|---|
| R-SCOPE | أهلية الشريحة آليًا | ترفض unknown slice أو موافقة ناقصة أو رأسًا مختلفًا أو اعتماديات غير مستوفاة؛ إنجاز التوجيه لا يغلق الأب أو يحرر FC20-16 |
| R-PATH | عبور إيجابي وسلبي | سجل قبول Bus/Socket قبل أول أثر؛ مع تعطيل/رفض القبول يكون عداد provider calls وcontext writes صفرًا؛ يمنع direct service/handler/repository path القديم |
| R-V1 | تكافؤ المسار الحالي | نتائج Project Run/Finance/Decision/Snapshot وgolden vectors لا تتغير؛ AI v1 محلي ومعطل كما هو |
| R-AUTH | التفويض والعزل | رفض غير المدير حيث يلزم، مشروع/سياق/receipt لمستأجر آخر، tenant/module/socket من المتصفح؛ لا أثر أو تسرب |
| R-CONTEXT | سلامة كتابة واعتماد السياق | رفض state/hash المزورين والإيصال المتقادم أو النسخة المتغيرة؛ idempotency والتزامن والانقطاع لا يفسدان السجل |
| R-AI | حدود الذكاء | منع prompt injection والأدوات/أرقام Finance/Verdict، رفض schema/citations غير الصالحة، امتناع دون passages معتمدة |
| R-POLICY | سياسة المصدر والموقع والإيقاف | رفض المصدر غير المقبول وغياب موافقة الموقع؛ الإيقاف يمنع الطلبات الجديدة والإعادة؛ لا ادعاء إلغاء طلب أرسل |
| R-FAIL | الفشل والمحتوى | علامة سر اختبارية لا تظهر في UI/ملخص/تدقيق؛ رسالة عربية مفهومة وإجراء تعافٍ، no direct fallback؛ حدود المهلة والإعادة |
| R-FREEZE | حدود التجميد والتراجع | تغير البصمات المصرح بها فقط، no parallel runtime/bus/AI socket، تراجع إلى إصدار known-safe مع سلامة البيانات وبقاء منافذ التجاوز القديمة معطلة؛ لا رجوع إلى baseline يعيدها ولا مسار مباشر بديل |

الدليل لكل شريحة: head SHA، paths، أسماء اختبارات ونتائجها وworkflow/artifact، مراجعات على الرأس نفسه، compatibility/rollback، ومخاطر متبقية. لا يخفض اختبار الأمان/العزل/سلامة البيانات بدعوى الاقتصاد؛ لا تعاد اختبارات غير متأثرة دون سبب. لا تستبدل خطة اختبار بدليل نجاح أو قبول جاهزية. TestSprite غير المفعّل ليس بوابة لهذه المرحلة.
