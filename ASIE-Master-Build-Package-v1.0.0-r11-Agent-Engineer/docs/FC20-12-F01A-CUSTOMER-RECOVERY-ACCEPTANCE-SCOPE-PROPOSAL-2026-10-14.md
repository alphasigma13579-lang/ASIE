## 3. مصدر الحقيقة والقراءة والحفظ — التصميم المقترح

### 3.1 القراءة والاختيار

1. يعاد استخدام GET جلسات DIB القائمة عبر عميلها وبوابة tenant الحالية؛ لا تفتح workspace قاعدة DIB مباشرة، ولا تنشأ خدمة أو API بديل.
2. تبقى `dib.read` و`dib.write` وصلاحيات الاعتماد مستقلة. في `dib_tenant_api.py` يعاد استدعاء `require_project_access` القائم بعد binding وقبل القراءة/الحفظ. لا تعتمد ملكية حالية على رابط قديم فقط.
3. قائمة الجلسات الحالية تستبعد المغلق وترتب updated_at ثم created_at ثم session_id. الأحدث زمنيًا ليس شهادة بأنه أصل تحرير المستخدم. يثبت التعافي جلسة المصدر؛ الدخول العام يوضح الجلسة المختارة، ولا يبدلها بصمت أثناء التحرير.
4. قراءة متسقة تعيد مرجعًا خادميًا للنسخة من السجل الفعلي: session/project وblueprint ID/revision/payload_hash ومؤشرات Manifest/Gate. لا hash محسوب في المتصفح ولا ادعاء payload بديل.
5. الاستجابة والعودة مربوطتان بالمؤسسة والمشروع والجلسة والنسخة والعنصر. تبدل النطاق/النسخة يبطل النتيجة القديمة قبل تطبيقها. البيانات البروتوكولية اللازمة لا تظهر في النصوص أو accessible names أو إشعارات العميل.
6. غياب جلسة أو Manifest أو سبب موثوق حالة صريحة غير مكتملة؛ لا يستدعي العرض builder أو project-run-readiness أو Finance لاستكمالها خفية.

### 3.2 CAS عند حد الحفظ الواحد

هذا امتداد عقدي مقترح، لا وصف للحفظ الحالي:

- أمر حفظ ذي إصدار موثق، مقترح تسميته `dib.blueprint.write.v2`، على المسار القائم؛ لا إعادة تسمية Blueprint v1 أو تغيير حساباته.
- كل تحديث لأصل موجود يتطلب هوية وبصمة ونسخة الأصل المتوقعة. يعيد الخادم تحميل الأصل ويطبق التعديل المسموح، ثم يفحص CAS داخل `BEGIN IMMEDIATE` عند حد persistence نفسه لكل الكتّاب؛ لا فرع «عميل موثوق» يتجاوز الحارس.
- ينشئ الخادم معرف Blueprint جديدًا وrevision تالية؛ لا يستبدل صف الأصل ولا يعيد استخدام معرفه. تحديث المؤشر يفعّل إبطال Manifest/Gate القائم. لا إصدار اعتماد أو Gate تلقائي من التعافي.
- الإنشاء الأول حالة مستقلة يثبت فيها عدم وجود أصل ذريًا. الطلب القديم الذي يحاول تحديث أصل بلا توقعات يرفض بأمان؛ هذا أثر توافق معلن، وليس تغييرًا كاسرًا صامتًا.
- يرحّل `DIBWorkspace` و`DIBIntakeItemGovernance` و`DIBManifestRunReadiness` إلى توقعات نسخة التحرير الأصلية. لا يجلب العميل أحدث hash قبيل الحفظ ليخفي تعارضًا.
- التعارض أو فشل الكتابة لا يغير صفوف الأصل أو مؤشرات السلسلة أو أحداث نجاحها. تظل تعديلات المستخدم قابلة للمراجعة، ولا يعاد إرسالها تلقائيًا فوق نسخة أحدث.
- النجاح لا يعلن من item-decisions أو من فتح الحقل؛ يلزم إتمام الحفظ وإعادة قراءة المصدر والتحقق من زوال النقص المحدد.
- حفظ نقص DIB يعدل مصدر DIB؛ حفظ نقص المشروع يعدل المشروع؛ إصلاح الدليل يمر بمالك الدليل. تشابه أسماء الحقول ليس ربطًا بين مصادرها.
- أول إنشاء في اختبارات HTTP وprivate-smoke لا يستلزم تغيير أدوات النشر إذا بقي متوافقًا. لا يُعد هذا إذن تشغيل تلك الأدوات.

### 3.3 الخطأ والتاريخ والصلاحيات

تغلق أكواد الخطأ في `dib_api.py` وحد GET المباشر في `dib_tenant_api.py` وحد رفض payload السابق لهما في `dib_http_mounting.py`. لا تمرر str(exception) أو أسماء مفاتيح عميل حساسة إلى الرد أو التدقيق المعروض. تحفظ رموز بروتوكولية آمنة ومعنى عميل محلي؛ العطل غير المصنف لا يسمى نقص مدخل أو عطلًا مؤقتًا معلومًا.

المسودة الحالية وSnapshot التاريخي مصدران موسومان منفصلان؛ لا تستعمل remediation قديمة لإغلاق نقص حالي ولا تعدل Snapshot. تبقى صلاحيات `project.edit` وعزل Dataset والتحقق من assumption/criterion والجودة وقت الربط. مراجعة المصدر تتطلب `platform.manage` كما هي؛ يرى غير المخول السبب والدور المسؤول دون زر يرفع صلاحياته. لا فتح لبوابة EngineeringSurfaceGate.

## 8. قبول بدء الخدمة والصيانة — شرط منفصل محفوظ

اتجاه الصيانة المخططة أساس الإعداد، وليس تصريح تشغيل قاعدة فعلية. [تصميم الفهرس §3](FC20-12-F01A-AUDIT-ORIGIN-INDEX-SCOPE-PROPOSAL-2026-10-11.md) و[الاستئناف المشروط §4](FC20-12-F01A-INDEX-CONDITIONAL-RESUME-PROPOSAL-2026-10-11.md) يحفظان بوابة الإتاحة.

[قياسات اصطناعية سابقة](https://github.com/alphasigma13579-lang/ASIE/pull/189#issuecomment-6112402770): 1k/100k/1m صف، تهيئة نحو8/136/1398ms ونمو نحو64KB/6.3MB/64.3MB. ليست SLO ولا قبولًا لبيئة المالك. مهلة انتظار القفل30 ثانية ليست حد بناء الفهرس.

خطة تأهيل مقترحة فقط: بيئة ممثلة وحجم/توزيع متفق عليهما، عشر تهيئات باردة على نسخ مؤقتة مستقلة، وتزامن عمليتين على الأقل أو العدد المعتمد الأكبر؛ قياس إنشاء الفهرس وAPI حتى الجاهزية والمساحة والتحقق والاستعادة. تتبع اختبارات القفل تحت/فوق المهلة والانقطاع وإعادة الفتح وسلامة الصفوف والتراجع القائم. تُستكمل الفجوات فقط ولا تعاد أدلة سليمة بلا سبب.

اقتراح تقدير نافذة الصيانة: ضعفا أسوأ زمن بروفة كاملة تشمل الفحص والتهيئة والتحقق والاستعادة؛ **صيغة غير معتمدة** وليست إذن تشغيل. تعرض النافذة الرقمية ووقت قرار الاستعادة لاحقًا لاعتماد المالك. ما زالت البيئة الفعلية وحجم/نمو البيانات وقيد التزامن والحد المقبول ومسؤول الاستعادة غير مثبتة. لا قبول production placement قبلها. التراجع البرمجي لا يسقط الفهرس؛ لا DROP أو retry مفتوح أو live migration من هذه الوثيقة.
