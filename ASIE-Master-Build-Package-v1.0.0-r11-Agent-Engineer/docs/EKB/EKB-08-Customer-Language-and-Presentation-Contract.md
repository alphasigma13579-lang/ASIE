# EKB-08 — عقد لغة العميل وعرضه

| الحقل | القيمة |
|---|---|
| المعرف | `ASIE-EKB-08-Customer-Language-and-Presentation-Contract-v1.0.0-AR` |
| الحالة | `BINDING / REMEDIATION OPEN` |
| المالك | Product & Engineering |
| النطاق | كل واجهة عميل، تقرير، مذكرة قرار، تصدير، رسالة حالة، ومساعد «سند» |
| آخر مراجعة | 2026-09-05 |
| لا يغيّر | Finance أو Snapshot أو AAS أو Decision Council أو مصدر الحقيقة التاريخي |

## القرار الملزم

العربية هي اللغة الافتراضية والكاملة لعميل ASIE. عند اختيار العربية، لا يظهر في تجربة العميل نص إنجليزي أو رمز داخلي أو معرّف تقني إلا في الاستثناءات المحددة هنا. عند اختيار الإنجليزية، تكون التجربة كاملة بالإنجليزية بالقاعدة نفسها.

هذا عقد **عرض وتجربة** لا ترجمة كلمات فقط: كل نص عميل يوضح المعنى العملي، أثر الحالة، والخطوة التالية الممكنة.

## نطاق العميل

يشمل العقد صفحات الويب والنوافذ والنماذج والأزرار وحالات الخطأ والانتظار؛ صفحات القرار والأدلة والتنفيذ واختبار الواقع والتقارير؛ HTML وPDF وDOCX وPPTX والمذكرة؛ «سند» وروابط العودة؛ وأي استجابة API يعرضها العميل.

لا تدخل سجلات التدقيق أو السجلات التشغيلية أو تفاصيل المزوّدات في تجربة العميل. تبقى في واجهة مشرف محمية بصلاحية `platform_admin`، خارج تنقل العميل الافتراضي.

## قاعدة اللغة

### عند `locale=ar`

1. الاتجاه RTL.
2. تترجم كل التسميات والحالات والإجراءات والتلميحات والتقرير والمذكرة والتصدير.
3. تستخدم عبارة عربية مفهومة للأعمال، لا ترجمة حرفية لاسم برمجي.
4. تشرح كل حالة مانعة: ما الذي ينقص؟ لماذا يهم؟ وأين يكمله المستخدم؟
5. تحفظ اللغة في الحساب والرابط والتصدير نفسه.

### عند `locale=en`

1. تكون الواجهة والتقرير والمذكرة والتصدير بالإنجليزية الكاملة.
2. لا يظهر نص عربي إلا عنوان مصدر أصلي أو اقتباس لازم، مع وصف مفهوم.
3. لا تصبح الإنجليزية مبررًا لعرض معلومات تقنية داخلية.

### الاستثناءات الضيقة

يبقى النص الأصلي فقط إذا كان اسم علامة/مصدر رسمي، أو اختصارًا ماليًا متعارفًا مع شرح عند أول ظهور، أو اقتباسًا لازمًا. لا تعد أسماء المراحل الداخلية أو العقود أو المحركات أو المعرفات استثناءً.

## حظر التسرب التقني

يُمنع في العميل أو وثائقه عرض:

- `project_id` و`run_id` و`snapshot_id` و`profile_id` و`contract_id` و`review_id`.
- hashes وأسماء العقود والمحركات والخوارزميات ومراحل التنفيذ.
- `REVIEW_REQUIRED` و`NOT_READY` و`DEMO_OR_USER_INPUT_ONLY` وrule codes وأسماء متغيرات البيئة.
- `setup` و`procurement` و`staffing` و`launch` و`stabilization` و`no_evidence_links` وما يماثلها.
- تشخيصات مزوّدات أو أخطاء خامة أو بيانات تدقيق.

تستبدل طبقة العرض كل قيمة داخلية بـ:

`عنوان العميل → المعنى العملي → الأثر → الخطوة التالية → رابط الإكمال`.

طبقة العرض لا تغيّر نتيجة مالية أو Snapshot أو قرار؛ هي تشتق عرضها من المصدر المحفوظ فقط.

## المدخلات الناقصة و«سند»

عند عدم اكتمال التقرير أو القرار، تعرض المنصة قائمة مرتبة بالمدخلات الإلزامية الناقصة، والغرض التجاري لكل مدخل، والحقل المميز في موضعه. يوفر «سند» زرًا ينقل إلى الحقل أو المصدر الصحيح، ثم يعيد المستخدم إلى موضعه السابق بعد الإكمال.

«سند» مساعد تنقل محلي وحتمي؛ لا يفسر ولا يعدل الحقيقة المالية أو القرار.

## التقارير والقرار

- تسمى صفحة العميل «حالة التقرير» لا «سجل الإصدار».
- لا تعرض مراجع Snapshot أو hashes أو بيانات المراجعة الداخلية.
- عند نقص المدخلات، تظهر «مسودة غير مكتملة» مع قائمة إكمال، ويمنع تصدير وثيقة تمويل نهائية.
- التقرير والمذكرة نسخة عرض مؤرشفة حسب اللغة وإصدار العرض، مشتقة من Snapshot نفسه بلا تعديل للّقطة.
- تعرض الأدلة: المصدر والحداثة/الحدود ودرجة الثقة؛ ولا تعد بنجاح أو تمويل.

## بوابة القبول

لا يبدأ تغيير يمس العميل، ولا يعلن اكتمال تعريب أو تجربة، قبل:

1. جرد قابل للتدقيق لكل مسارات العميل والشاشات والنوافذ والتصديرات.
2. حالة `AR` و`EN` ورابط اختبار واستثناء موثق لكل عنصر.
3. اختبار متصفح للمسارين على الهاتف وسطح المكتب وRTL والتكبير ولوحة المفاتيح.
4. اختبار يمنع النص التقني والرموز الداخلية في المسارين.
5. اختبار «أكمل المدخل» و«سند»: انتقال للحقل الصحيح، حفظ، وعودة.
6. اختبار لغة HTML وPDF وDOCX وPPTX والمذكرة.
7. مراجعة بشرية بصرية للصفحات المتغيرة.

الفشل في أي بند يعني `REMEDIATION OPEN`؛ لا يوصف التعريب بالمكتمل، ولا تفتح دعوات بيتا جديدة استنادًا إلى اكتمال شكلي.

## المخالفات القائمة

الصور المبلّغ عنها في 2026-09-05 دليل على مخالفات قائمة، لا حصر كامل:

- معرّفات ومراجع وحالات داخلية في حالة التقرير.
- مراحل تنفيذ وقواعد ومعالجات مخاطر بالإنجليزية أو بصيغة برمجية.
- `Snapshot` ومعرّفات وقيم وسيطة أمام العميل.
- ملفات تمويل وقطاعات كمعرفات تقنية بدل وصف أعمال مفهوم.
- خلط العربية والإنجليزية في القرار والأدلة والتقارير.

التصنيف: `Defect — High — Customer-facing language and technical-leakage breach`.

## قواعد التغيير والإغلاق

- يقرأ هذا العقد قبل أي تنفيذ أو مراجعة أو إصدار، ولو كان التغيير خلفيًا وله أثر ظاهر للعميل.
- الاستثناء الجديد يحتاج سببًا ونطاقًا ومالكًا وتاريخ مراجعة واختبارًا.
- يبقى أي تعديل Finance أو Snapshot أو AAS أو Decision Council خاضعًا لعقده المجمّد وACR مستقل.
- لا تفعّل مزودًا حيًا أو تدعو مستخدمين جدد للتغطية على عيب تجربة العميل.
- لا يغلق العلاج قبل جرد 100%، وصفر تسرب غير مصرح به في الاختبارات والتصديرات، ونجاح اختبارات اللغة والتنقل، ومراجعة بصرية عربية مستقلة، وإثبات سلامة الأسطح المجمّدة.
