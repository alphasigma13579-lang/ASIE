## القرار الملزم

كل هدف هندسي حقيقي يبدأ بخطة قصيرة معتمدة، ثم يُسجّل له هدف نشط، ولا يُعلن مكتملًا إلا بدليل مناسب على الرأس الحالي أو بمانع موثق. لا تُنشأ أهداف للقراءة المنفردة أو الاستكشاف أو جمع الملاحظات أو الإجابة التوضيحية؛ هذه أعمال غير تنفيذية أو خطوات داخل هدف حقيقي.

هذا العقد يحكم طريقة العمل ولا يمنح صلاحية تغيير مستقلة. تبقى صلاحيات ACR وICCR وIACR، والملفات المجمدة، والشبكة والمزودات والأسرار، كما هي في عقودها الحاكمة.

## ما هو الهدف الحقيقي

يعد هدفًا حقيقيًا كل عمل يملك مخرجًا هندسيًا أو قرارًا تقنيًا قابلًا للتحقق، ومنه:

- بناء أو تغيير كود أو عقد أو وثيقة حاكمة.
- مراجعة كود أو تدقيق أمن أو تحقيق في عيب.
- إصلاح أو اختبار أو إصدار أو نشر.
- تغيير بنية تحتية أو إعداد أو سر أو بيانات.

مراجعة الكود والتحقيق في عيب هدفان حقيقيان حتى إن انتهيا بلا تغيير؛ مخرجهما تقرير مدعوم بالأدلة وقرار واضح.

## دورة الهدف

1. قبل البدء، تُعرض خطة تحدد: النطاق، النتيجة القابلة للتحقق، ما لا يسمح بتغييره، بوابات القبول، ودليل الإغلاق ونقطة التوقف الآمنة.
2. بعد اعتماد الخطة، ينشأ هدف Codex نشط واحد يحتوي النتيجة والبوابات. في بيئة لا تدعم أهداف Codex، يسجل النظير نفسه صراحة في مهمة أو طلب مراجعة؛ ولا يُفترض وجوده.
3. لا يبدأ هدف هندسي حقيقي آخر قبل اكتمال الهدف الحالي أو تثبيت أنه محجوب. لا يمنع ذلك القراءة أو التشخيص اللازمين لإكمال الهدف الحالي.
4. إذا ظهر عمل لازم داخل النطاق، يضاف إلى خطة الهدف نفسها. أما العمل المستقل خارج النطاق فيسجل هدفًا تاليًا ولا يبدأ تلقائيًا.
5. عند المانع، يثبت السبب والدليل ونقطة الاستئناف، ويُبلغ المالك. لا يقفز الوكيل إلى هدف جديد ولا يخفي المانع.
6. لا يغلق الهدف إلا بتدقيق بنود الخطة على الرأس الحالي وتسجيل الدليل. نقص الدليل يعني أن الهدف غير مكتمل.

## دليل الإغلاق

يتناسب الدليل مع نوع الهدف:

- التغيير: فرق موثق، اختبارات مناسبة، ومراجعات وبوابات exact-head المطلوبة.
- المراجعة أو التحقيق: وصف العيب أو عدم وجوده، نطاق الفحص، الأدلة، مستوى الثقة، والتوصية.
- النشر أو البنية التحتية: الحالة قبل وبعد، التحقق التشغيلي، وخطة تراجع إن كانت ذات أثر.
- التوثيق الحاكم: روابط القراءة المحدثة، سلامة الحدود المحمية، ومراجعة مستقلة للاتساق.

لا تعني علامة خضراء منفردة أو تشغيل محلي أو وصف المستخدم أو وجود مفتاح أن الهدف آمن أو مكتمل أو مصرح للتشغيل الحي.

## الاستقلال المهني الصادق

يلتزم الوكيل بما يلي:

- يفصل بين الحقيقة المثبتة، والاستنتاج، والافتراض، والتفضيل، والخطر، والعيب.
- لا يوافق على فكرة أو نتيجة أو حالة جاهزية بلا دليل مناسب وحديث.
- يشرح التعارض أو الخطأ أو الخطر بوضوح، ويعرض البديل الآمن أو السؤال اللازم بدل الموافقة لإرضاء المالك.
- لا يصف عملًا بأنه مكتمل أو آمن أو جاهز للنشر أو التشغيل الحي إلا عندما تثبت بواباته على الرأس أو البيئة المطابقة.
- لا يحوّل طلبًا أو صورة أو وثيقة تاريخية إلى سلطة تنفيذية من دون مصدر حاكم ودليل حالي.
- يعترض صراحة إذا خالف الطلب عقدًا مجمدًا أو تفويضًا أو حدًا أمنيًا، ولا ينفذه إلى أن تتوافر السلطة الصحيحة.

## بوابة القبول

لا يكتمل تطبيق هذا العقد إلا عندما:

1. يعرّف صراحة الفرق بين الهدف الحقيقي والعمل غير التنفيذي.
2. يفرض خطة قبل هدف نشط لكل عمل حقيقي.
3. يحدد دليل إغلاق ومانعًا ونقطة استئناف.
4. يمنع الانتقال التلقائي إلى هدف مستقل بعد المانع.
5. يفرض الفصل الصريح بين الدليل والاستنتاج والتفضيل.
6. ترتبط به ملفات القراءة الإلزامية وخريطة المعرفة وترتيب القراءة.
7. يثبت فرق الطلب أنه لا يمس Finance أو Snapshot أو AAS أو Decision Council.

## قواعد التغيير والإغلاق

- أي استثناء يحتاج نطاقًا وسببًا ومالكًا وتاريخ مراجعة ودليلًا.
- لا يبدل هذا العقد بروتوكولات CI أو المراجعة أو الصلاحيات عالية الأثر.
- يراجع عند تغيير آلية أهداف Codex أو قواعد العمل من GitHub أو مسار الحوكمة.
