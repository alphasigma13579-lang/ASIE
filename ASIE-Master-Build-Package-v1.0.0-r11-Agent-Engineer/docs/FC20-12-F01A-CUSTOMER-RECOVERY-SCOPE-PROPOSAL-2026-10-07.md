## 3. لماذا هذه التوسعة ولماذا لا نبني الآن؟

[خطة F-01 الأصلية §3/4/5](FC20-12-F01-TRUSTED-CONTEXT-INGRESS-REPAIR-PLAN-2026-10-01.md) تفرض الرسالة والتعافي، وتلزم عرض أقل توسعة قبل كود واجهة خارج القائمة. blob الوثيقة الحاكمة يبقى `c80cb6adaa442f43c98da7b9eb34c7cc9dcd9521` دون تعديل أو إعادة تثبيت البصمة.

الاختيار المقترح: **إعادة استخدام جزئية للملاحة واللغة وسند، وعرض مشتق فقط من حالة مصرح بها؛ لا قناة تنفيذ أو سلطة ثقة جديدة.** عرض المنع وحده لا يصحح توجيه المزودات ولا يستعيد القدرة الخام ولا يعوّض اختبار الطلب المباشر.

البدائل المرفوضة:

- إنشاء واجهة تستدعي Pre-Run الخام لعرض الرفض ثم إعلان نجاح T-08: يصنع مستهلكًا غير لازم ويتجاوز الغرض.
- استخدام market-context أو narrative الحاليين كالتفاف على المنع: المسار الموجود ليس دليل امتثال AAS ولا بديلًا معتمدًا.
- اختراع resolver أو proxy أو service/bus/socket جديد داخل التعافي: توسعة معمارية غير مصرح بها.
- إسقاط T-08 أو تخفيف الحارس أو تعديل خطة مثبتة لتنجح الفحوص: يخفي العيب بدل علاجه.
- تحليل نص استثناء أو سجل أو hash داخل المتصفح لاستنتاج صلاحية أو نقص: يجعل العرض مصدر قرار غير موثوق.

## 4. مصدر الحالة والحد المعماري — بوابة قبل كود العرض

قبل عرض تنفيذ هذه التوسعة للمالك، يلزم حصر محصور يثبت لكل حالة:

1. مالكها الخادمي والعقد والمسار المسجل، وموضع تحقق الجلسة والمؤسسة وملكية المشروع قبل القراءة أو replay.
2. كيفية وصول حالة آمنة إلى المستهلك الموجود أو المسموح، دون استدعاء raw contexts/pre-runs أو أي provider أو إنشاء سياق/اعتماد.
3. الفصل بين «قدرة غير متاحة»، و«نقص مدخل معلوم»، و«نقص دليل معلوم»، و«انتهاء جلسة/عدم صلاحية»، و«فشل غير مصنف». لا يُختلق نقص دقيق من منع عام.
4. الربط الفعلي للمشروع/مرجع المدخل أو الدليل ونسخته، وشرط منع نتيجة متأخرة بعد تبدّل المشروع/المؤسسة/الجلسة.
5. مصدر اللغة المحفوظ المتحقق خادميًا؛ غيابه/عدم صحته ⇒ العربية، وen الصحيح ⇒ الإنجليزية. مبدل المتصفح للعرض لا يمنح صدقية أو صلاحية لاستجابة خادمية.
6. لا نقل بيانات خام أو سر أو سجل داخلي للعميل «كي ينقحه». المعرفات اللازمة للربط تبقى داخل الآلية ولا تظهر في نص العميل أو diagnostics أو أحداث تحليلات جديدة.

**إن لم يوجد مصدر/مستهلك يحقق ذلك ضمن العقود النافذة، تتوقف شريحة الربط، ويعرض النقص واعتماديته على المالك قبل أي كود.** لا يعطي هذا المقترح موافقة إنشاء API/تغيير عقد أو تنفيذ F-01B أو routing_repair. قد يعتمد الربط على استعادة البناء الموثوق لاحقًا؛ لا نفترض جاهزيته ولا نضغط لتجاوزه لإنهاء F-01A.

المسار المحظور: واجهة أو سند → خدمة/مخزن/مزود/محرك مباشرة، أو أي تشغيل ذكاء جديد من التنقل. المسار المسموح لهذه التوسعة، بعد إثبات مصدره، هو **حالة آمنة من المصدر الحاكم → عرض محلي → ملاحة محلية في المشروع نفسه → إجراء المستخدم عبر مسارات المشروع/الأدلة القائمة والمصرح بها → عودة للعرض**. هذا مسار عرض، لا بديل لخط تشغيل AAS.

كل تشغيل فعلي يبقى داخل مسار AAS المجمد وفق [دليل الحزمة](../AGENTS.md)، وتخضع أعمال إصلاح التوجيه لاعتمادياتها المنفصلة في [ACR التوجيه المقترح](ACR-AIA-ROUTING-REMEDIATION-2026-09-27.md)؛ لا يصبح ذلك المقترح معتمدًا أو منفذًا بالإحالة إليه هنا.

## 5. عقد السلوك المقترح — الجزء المعني فقط من الرحلة

المستخدم: مالك/عضو مسموح داخل مشروعه، باللغة المحفوظة. النتيجة: يفهم المنع وحدوده، ينتقل عند وجود نقص معلوم إلى موضعه، ويحفظ عمله ويعود إلى موضع البداية؛ لا وعد بتشغيل محجوب.

| الخطوة | سؤال المستخدم/فعله | سطح العرض والاستجابة | البيانات والصلاحية | الفشل والتعافي | دليل النجاح المطلوب لاحقًا |
|---|---|---|---|---|---|
| ظهور المنع | لماذا لم يكتمل الإجراء؟ | معنى أعمال + أثر محدد + إجراء ممكن؛ لا نص فني | حالة آمنة مرتبطة بالمشروع من المصدر المثبت في §4 | غير مصنف ⇒ رسالة آمنة بلا اختراع نقص/صلاحية | استجابة الخادم الفعلية تصل إلى السطح الصحيح؛ اختبار معزول وحده لا يثبت الربط |
| الانتقال | أين أكمل المدخل/الدليل؟ | زر محدد إن كان الهدف معلومًا، وإلا «العودة إلى المشروع» | ربط محلي مغلق بمرحلة/هدف معلوم، لا URL حر من الاستجابة | غياب/انتهاء مرجع ⇒ لا انتقال إلى أول عنصر عشوائي | المشروع والهدف والتركيز صحيحون، ولا طلب مزود أو إنشاء سياق |
| تعديل المستخدم | هل حفظت ما أكملته؟ | يظل الحفظ عبر مالكه الحالي وبفعل صريح للمستخدم | لا مراجعة أو اعتماد تلقائي ولا تعديل Snapshot | فشل الحفظ يبقي المدخلات ويعرض إجراء آمنًا | لا ادعاء حفظ قبل نجاح المسار الفعلي؛ صلاحية وعزل |
| العودة | كيف أعود؟ | استعادة المرحلة والموضع والتركيز عند صلاحية المرجع | لا تخزين نص دليل أو GPS خام أو token في سجل العودة | تبدّل جلسة/مؤسسة/مشروع يبطل المرجع؛ هدف مفقود ⇒ موضع آمن في المشروع الحالي | حفظ ثم عودة/Back/Forward/Refresh بالحدود الموثقة دون سياق قديم |
| استمرار الحجب | أكملت الدليل، فلماذا لا تعمل القدرة؟ | يوضح أن تجهيز المعلومات لا يفتح قدرة غير معتمدة | لا تغيير flags/إيصالات أو صلاحية من العرض | لا إعادة محاولة raw أو fallback لخط محجوب | صفر تشغيل جديد مع بقاء المنع مفهومًا |

- العربية كاملة افتراضيًا وRTL؛ الإنجليزية كاملة عند اختيارها. لا IDs/hashes/contracts/engines/provider names أو حالات برمجية في النصوص أو accessible names.
- سند دليل محلي حتمي: يوجّه فقط إلى هدف العرض المعلوم؛ لا يجلب/يولّد بيانات، لا يعتمد أدلة، لا يصدر قرارًا، لا يرفع صلاحية.
- سياسة العودة المقترحة تحفظ الحد الأدنى داخل سياق الجلسة؛ لا تُمدد مدة تخزين بيانات أو تجمع telemetry. الروابط المرحلية لا تتجاوز تحقق الخادم. تبدّل النطاق يلغي المرجع قبل معالجة نتيجة قديمة.
- حالات loading/blocked/empty/permission/expired/offline/recovery تُحدد بحسب ما يثبته مصدر §4، لا قائمة حالات شكلية تعطي انطباع تنفيذ غير موجود.

تجمع التغييرات المتماسكة قبل الفحوص، ولا تعاد فحوص ناجحة غير متأثرة بلا سبب. بوابات CI الإلزامية تبقى؛ TestSprite غير المفعّل ليس بوابة. بعد التنفيذ، لا تُغلق T-08 إلا بأدلتها كاملة على الرأس الموافق؛ لا يُكتب N/A بسبب غياب الربط. تراجع نتائج CodeRabbit/Copilot عند التوافر على الرأس نفسه؛ rate limited/skipped ليس مراجعة ناجحة، وتدقيق Codex لنفسه ليس اعتمادًا مستقلًا.

## 8. بوابة التنفيذ والمخاطر والتراجع

**الحالة الآن: التصميم والربط غير جاهزين للتنفيذ.** شروط عرضه للتنفيذ:

1. مراجعة اتساق هذا المقترح ومراجعته المستقلة، ثم اعتماد المالك تصميمه بموضوع محدد؛ لا نقل موافقته على الإعداد إلى موافقة التصميم.
2. إثبات §4؛ أو إعلان المانع واعتماديته بدل إنشاء مصدر موازٍ. اكتشاف حاجة F-01B أو التوجيه أو تغيير API يوقف الربط ويُعرض منفصلًا تحت سلطته الحالية.
3. قائمة ملفات واختبارات نهائية ضيقة، وتسجيل النطاق/الانتقال إن تطلبته الحوكمة النافذة، مع الحفاظ على موضع تنفيذ واحد وقرارات وتاريخ وبصمات النطاق السابق.
4. استئناف تنفيذ منفصل مصرح بعد نفاذ البوابات، دون تشغيل شبكة/مزودات/نشر. PR كود مستقل يحصر فرق الواجهة ولا يخلط أدلته أو موافقاته برأس #189.
5. أدلة القبول ثم مراجعة وقرار دمج منفصل. تسليم العرض لا يغلق F-01 أو FC20-08/09/11 أو ضوابط routing_repair أو EKB-08 الشامل.

الأثر الحالي **توثيقي منخفض تشغيليًا، ومهم حاكمًا**. التنفيذ اللاحق **متوسط** لسلوك الملاحة/حفظ العمل، و**عالي الأهمية** في عزل السياق وصحة مصدر الحالة؛ لا ضمان «لن ينحدر» من الخطة وحدها. التراجع لاحقًا إلى نسخة العرض السابقة فقط، مع بقاء الرفض الخادمي وعدم استعادة raw trust/provider bypass أو تغيير البيانات التاريخية.

التوثيق الحالي يحقق فرق/روابط واتساق حدود فقط؛ لا اختبارات تطبيق أو نشر أو أدلة متصفح جديدة. لا نعيد اختبارات #189 الخضراء لملف مقترح مستقل. نقص المراجعة أو المصدر يبقى مسجلاً.
