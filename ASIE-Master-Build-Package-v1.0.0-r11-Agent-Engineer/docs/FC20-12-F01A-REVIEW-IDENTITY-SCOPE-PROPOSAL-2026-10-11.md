## 3. العقد وحد إعادة الاستخدام

[AIA-02 §§10.2–10.3 و11.1–11.2](https://github.com/alphasigma13579-lang/ASIE/blob/a3be7cfc42c7ab5427343f95df0b795ed50ab0ac/ASIE-Master-Build-Package-v1.0.0-r11-Agent-Engineer/docs/AIA-02-Intelligence-Operating-Architecture-v1.2.1.md#L658-L758) يثبت السياق المقفل والبصمة والهوية وربط المراجعة والإيصال به. لا يجيز تناقض هوية مخزنة بتجاهلها.

[المصدر الحالي](https://github.com/alphasigma13579-lang/ASIE/blob/3cf88c7bae98a48c5cd950df978678f452501980/ASIE-Master-Build-Package-v1.0.0-r11-Agent-Engineer/backend/repository.py#L1655-L1790) يوفر بالفعل تحقق الشكل الثابت، والمقارنة ذات النوع بين JSON والصف، وإعادة تحقق lifecycle/component/hash عبر النموذج الأصلي عند `get_intelligence_context(validate_for_consumption=True)`. أما `_intelligence_review_context` فيستخدم صفًا داخل معاملة المراجعة/الاعتماد لكنه يعيد تركيب هوية SQL قبل فحص النموذج.

الإصلاح المقترح يعيد استخدام هذا التحقق القائم على **الصف نفسه المقروء من اتصال المعاملة نفسها** قبل بناء السياق المعتمد للمراجعة. يسمح باستخراج helper داخلي صغير مشترك بين الحدين لتجنب نسختين متباعدتين من التحقق؛ لا يستدعي getter يفتح اتصالًا أو تفويضًا ثانيًا، ولا يضيف مصدر ثقة أو resolver.

القيود:

- تبقى المصادقة والصلاحيات والمؤسسة والمشروع قبل الوصول، و`BEGIN IMMEDIATE` وحد الإدراج/rollback كما هي.
- يبقى رفض المراجعة غير المؤهلة `context_not_review_eligible`، ورفض استهلاك السياق `context_integrity_invalid`. لا يمسك helper أخطاء التخزين غير المتوقعة ليحوّلها إلى قبول أو خطأ نطاق مضلل.
- معالج HTTP الحالي يحوّل ValueError في مراجعة/اعتماد السياق إلى invalid/400 آمن؛ لا عقد استجابة جديد ولا نقل 409 من مسار narrative إلى هذا المسار.
- القراءة التاريخية العادية تبقى على عقدها؛ لا فرض إثبات منشأ على جميع القراءات أو على سياق أصلي صالح قديم بلا proof جديد. لا backfill أو إصلاح صامت أو حذف بيانات أو إعادة ختم.
- يبقى تحقق ReviewOverlay وApprovalReceipt وشروطهما وبصماتهما ونطاقهما كما هو؛ لا مقيّم شروط جديد. لا تغيير استعلام المنشأ أو الفهرس أو SQLite schema أو contract/model أصلي.

التوافق المقصود: رفض السجل المخزن غير المتسق قبل إنشاء مراجعة/إيصال، مع بقاء السياق الأصلي الصحيح قابلًا للمراجعة والاعتماد. قبول هذا الأثر يحتاج قرار النطاق المحدد؛ لا يفوضه تصميم محلي.

## 4. أصغر قائمة تطبيق مستقبلية

بعد التسجيل والاستئناف المراجعين والمصرح بدمجهما فقط:

1. `backend/repository.py`: مشاركة التحقق القائم واستدعاؤه داخل حد المراجعة/الاعتماد المعاملاتي؛ بلا تعديل SQL/proof/schema/API.
2. `tests/test_repository_intelligence.py`: مصفوفة رفض/توافق لكلا الكتابتين، مع حالات نجاح تاريخية سليمة وسلامة rollback.

لا حاجة مثبتة إلى مسار عاشر أو تغيير ملف API أو test آخر. يعاد تشغيل الاختبارات المتأثرة القائمة دون تحريرها. إذا أثبت التنفيذ احتياجًا خارج هذين المسارين أو معنى عقد مختلفًا، يتوقف الجزء المتأثر ويعرض القرار؛ لا توسعة تلقائية.

## 5. قبول الإصلاح المستقبلي — NOT_RUN

إعادة إنتاج §2 منفذة؛ الاختبارات الآلية التالية وإصلاحها **NOT_IMPLEMENTED / NOT_RUN**:

- مصفوفة مستقلة لكل من حفظ المراجعة وحفظ الاعتماد؛ في الثانية تنشأ مراجعة صحيحة أولًا ثم يفسد السياق، حتى لا يحجب رفض المراجعة اختبار حد الاعتماد.
- JSON تالف، قيم غير object، حقول ناقصة/إضافية، أنواع scalar خاطئة بما فيها bool مقابل int، وهوية organization/project/context غير مطابقة، وتعارض state/version/hash/fingerprint/timestamps مع الصف.
- تغيير component material/lineage أو lifecycle مع بقاء label البصمة؛ رفض قبل إدراج overlay/receipt، دون تغيير السياق أو الدليل أو الصفوف السابقة. لا منع للتدقيق المصرح القائم؛ المقصود منع سجلات اعتماد جديدة.
- مصادقة/صلاحيات/مؤسسة/مشروع غير صالحين لا يصلون إلى التحقق أو يكشفون وجود سجل تالف؛ الحالة الصحيحة تحافظ على المعاملة وبصمات overlay/receipt ومراجعة الإنشاء الحقيقي.
- سياق أصلي صالح جديد، وسياق أصلي صالح بلا إثبات منشأ جديد، يظلان قابلين للمراجعة/الاعتماد؛ القراءات التاريخية المسموح بها لا تتغير. لا إحياء replay قديم غير مثبت.
- تثبيت رسائل الرفض الدقيقة لكل JSON تالف أو شكل/نوع/هوية غير صالحين؛ لا تسرب `context_idempotency_conflict` من إعادة الاستخدام ولا ابتلاع SQLite/storage failures. اختبار تنفيذي يثبت أن helper يستعمل اتصال المعاملة نفسه ولا يستدعي getter العام أو يفتح اتصالًا بديلًا.
- بوابة narrative والإيصال والمفتاح والذرية وCAS والعزل والفهرس تبقى ناجحة، مع أخطاء تخزين داخلية لا تُخفى؛ اختبارات مركزة ثم CI ومراجعات exact-head، لا نقل نتائج الرأس السابق.

## 6. مسار التسجيل المقترح وحد السلطة

يحكم الانتقال [عقد التسجيل §4](FC20-12-F01A-DEFENSIVE-ENABLING-REGISTRATION-PROPOSAL-2026-10-01.md) و[إلحاق الاستهلاك §6](FC20-12-F01A-APPROVAL-CONSUMPTION-SCOPE-ADDENDUM-2026-10-09.md). لا يسمح RESUME العاشر بإصلاح جديد لمجرد بقاء المسارات التسعة.

1. مراجعة هذا التصميم، ثم قبول مالك محدد لرأسه وأثر التوافق. نشر ملفي التصميم ودمجهما يحتاجان إذنهما؛ قرار الإعداد الحالي لا يمنحهما.
2. قرار إعداد/نشر تسجيل محدد، ثم PR حاكم منفصل: حفظ الأحداث العشرة والقرارات كما هي، وإضافة STOP_CHECKPOINT حادي عشر وSCOPE_EXTENSION ثاني عشر، مع `execution_authorized=false` حرفيًا وIN_PROGRESS والموضع الواحد محفوظًا ومحسوبًا. لا RESUME أو DELIVERED في التسجيل.
3. لا زيادة إلى `allowed_paths` التسعة: `added_paths=[]`. تبقى `allowed_schema_operations` وعملية الفهرس الوحيدة byte-exact، ولا عملية schema مضافة. موضوع التوسعة **دلالي** في حد المراجعة/الاعتماد، وليس اسم ملف جديدًا أو إذن schema.
4. يثبت موضوع قرار النطاق داخل غلاف القرار القائم: رأس التصميم وblob الحقيقيين، baseline/blob والسجل والحدث الأخير ورأس #189، المساران، حد التحقق واختبارات §5، وأثر الرفض وحد التوافق. يلزم oracle مستقل مغلق لهذا الموضوع؛ لا يكفي added_paths=[] أو رابط عام. يقترح القسم 6.1 التمثيل المغلق للمراجعة؛ لا نفترض أنه معتمد الآن ولا نضيف نموذج صلاحيات عام إلى أعلى السجل.
5. قائمة التسجيل المرشحة الدنيا هي الملفات السبعة القائمة: `/FOUNDATION-COMPLETE-20.json`؛ `tests/test_foundation_complete_20_program.py`؛ وثيقة FOUNDATION؛ `docs/EKB/FOUNDATION-COMPLETE-20-PACKAGE-INDEX.md`؛ خطة بيتا المالك؛ وثيقة تسجيل F01A؛ وثيقة تسجيل نطاق الاستهلاك. المسارات غير الجذرية نسبية للحزمة. تثبت القائمة الدقيقة والـoracles وprefixes قبل أي تحرير.
6. اختبارات التسجيل المستقبلية: العكس الكامل يعيد blob `d76e7b0f6d18a701985469664c0cb6c1f757c869` ثم سلسلة IRG→ISG→CRG→CS→RG→SG دون تخفيفها؛ أحداث وقرارات محفوظة، حدود raw bytes وأختام كل إسقاط، رفض Boolean الملتبس والحقول/المسارات/عمليات schema الزائدة، وإعادة استخدام قرار إعداد أو RESUME قديم أو true ضمن التسجيل. هذه الاختبارات NOT_RUN.
7. بعد مراجعة التسجيل وقرار دمجه المنفصل ونفاذه: قرار استئناف **جديد** مقيد بهذا الإصلاح ومعاملته واختباراته، وانتقال مراجع مستقل وموافقة دمجه قبل الكود. لا يعاد استعمال قرار الفهرس العاشر أو إذن إعداد هذه الوثيقة. تبقى قواعد مؤقتة/بيانات اصطناعية فقط؛ قبول startup للإنتاج لا يستنتج من أي true جديد.
