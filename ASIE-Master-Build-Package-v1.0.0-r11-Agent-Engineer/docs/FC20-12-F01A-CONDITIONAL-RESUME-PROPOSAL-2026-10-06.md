## 4. انتقال السجل والحارس المقترح — بعد قرار المالك فقط

الاختيار: إعادة استخدام الشريحة والسجل والحارس الحاليين؛ لا برنامج حالة أو Runtime أو Socket جديد. [الحارس المثبت](https://github.com/alphasigma13579-lang/ASIE/blob/65efaba85e7a5ca2c944486f88c15ab95a7bd5e5/ASIE-Master-Build-Package-v1.0.0-r11-Agent-Engineer/tests/test_foundation_complete_20_program.py#L356) يقبل السجل المتوقف فقط. لذلك لا تكفي علامة true أو fixture.

فرق السجل اللاحق محصور في **تغيير execution_authorized من false إلى true وإلحاق حدث RESUME واحد** في f01a_defensive_ingress. لا تغيير لأي حقل آخر في السجل الآلي كله.

حدث RESUME هو metadata حوكمة للمستودع، لا عقد تشغيل أو API. مجموعة مفاتيحه المقترحة المغلقة:

- type: RESUME؛ recorded_at: وقت تسجيل الانتقال الحقيقي بتوقيت UTC، لا وقت مفترض الآن.
- baseline_commit_sha: خط الأساس الموجود المحقق أعلاه؛ baseline_manifest_blob_sha: البصمة أعلاه.
- checkpoint: نسخة مطابقة كاملة من STOP_CHECKPOINT المثبت، مع سبب التوقف ومراجعه وشرطه.
- scope_extension: نسخة مطابقة كاملة من SCOPE_EXTENSION المثبت في #186؛ لا إعادة صياغة القرار القديم.
- owner_resume_decision: ID ورابط إيصال وتوقيت وموضوع وأثر وشرط لقرار المالك الجديد الحقيقي؛ subject يحدد baseline أعلاه وcheckpoint ونطاقه الموسع، ويربط المقترح المراجع بcommit/blob موجودين. أثره المحدد المقترح **F01A_DEFENSIVE_RESUME_ONLY**، وشرط النفاذ **REVIEWED_GOVERNANCE_TRANSITION_MERGED_AFTER_SEPARATE_OWNER_MERGE_APPROVAL**.
- effect: F01A_DEFENSIVE_RESUME_ONLY.

start_decision وsubject الأصليان يبقيان تاريخيين كما هما؛ موضوع الاستئناف الجديد يسجل في الحدث الجديد. لا SHA يحتوي نفسه، ولا main متحرك أو قرار مستمد من manifest. إذا تغير baseline يُفحص الفرق ويعرض تغير مادي قبل اعتماد الانتقال؛ لا نقل موافقة رأس قديم من ancestry وحدها.

يبقى state=IN_PROGRESS وactive_target نفسه ومحسوبًا، allowed_paths كما هي، delivery_evidence=null، closure_effect=NONE، environment=DARK_OFFLINE؛ network/provider/deployment=false. لا حدث DELIVERED أو START جديد، ولا فتح routing_repair أو تحرير FC20-05 أو إعلان اكتمال حزمة.

الحارس اللاحق يبني oracle مستقلاً من سجل #186 المثبت + فرق الاستئناف المحدد وقرار مالك مثبت في كود مراجع، وليس من مدخل السجل. مسار قبول الحالة الحالية يقبل هذا الاستئناف المحدد فقط بعد الانتقال؛ START وSTOP والتوسعة دون الاستئناف يبقون مراجع تاريخية مختبرة، لا بدائل لخفض الحالة الحالية. نموذج lifecycle المعزول يظل خارج قبول السجل الحقيقي.

يتكيف SG-05 بإنشاء تحقق انعكاسي جديد: إزالة حدث RESUME وإعادة العلم إلى false يعيدان **السجل الكامل** إلى blob #186 أعلاه؛ ثم يبقى تحقق عكس توسعة SG-05 السابق على النسخة المتوقفة لإثبات baseline السابق. تحفظ oracles القديمة واختبارات mutations، ولا يحذف assertion أو يوسع predicate عام لقبول الاستئناف.
