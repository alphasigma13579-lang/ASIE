- توفير استيراد متحقق من البيانات السابقة، مع الاحتفاظ بالأصل وعدم حذفه تلقائيًا.
- توفير نسخ واستعادة موثقتين، دون تشغيل ترحيل على بيانات المالك قبل موافقته.

القبول: نجاح الكتابات المتزامنة، والتعافي بعد الانقطاع، واستعادة نسخة مستقلة، وإعادة بناء الفهرس، واختبارات سلامة البيانات والصلاحيات والعزل.

### الخطوة الرابعة — إنشاء لوحة إدارة بمدخل مستقل

المدخل المعتمد في الخطة: https://betaasie.com/admin. ليس ادعاء وجوده الآن.

- واجهة إدارة مستقلة في العرض والتنقل عن مساحة العميل، ضمن التطبيق الحالي؛ لا تطبيق أو نطاق فرعي جديد.
- إعادة استخدام نظام الحسابات والجلسات القائم، مع صلاحية platform_admin تتحقق خادميًا لكل عملية.
- غير المسجل يُوجّه للدخول ثم يعود للإدارة؛ المسجل غير المخوّل يُرفض وصوله.
- لا يُمنح الامتياز بناءً على البريد أو الاسم وحدهما. يُتحقق من حساب المالك وعضويته؛ أي منح صلاحية يكون إجراءً منفصلًا موثقًا.
- النسخة الأولى تعرض: حالة الخدمات، حالة قبول المصادر، آخر فحص جاهزية، ملخصات تشغيل آمنة، وزر تعطيل الخدمات الخارجية.
- لا تعرض المفاتيح أو قيم الأسرار، ولا توفر تعديلها داخل المتصفح.
- زر الإيقاف يمنع الطلبات الخارجية الجديدة ومحاولات الإعادة؛ لا يدّعي إلغاء طلب أُرسل بالفعل.
- يبقى إعادة التفعيل إجراءً تشغيليًا محكومًا، لا زرًا يتجاوز الموافقات.

القبول: دخول المالك، رفض غير المدير عبر الواجهة والطلبات المباشرة، حماية العمليات المغيّرة للحالة، تدقيق الإيقاف، وعدم كشف الأسرار.

المؤجل: إدارة الدعوات والمستخدمين بصورة كاملة، ومحرر قبول المصادر.

### الخطوة السابعة — اختبار المالك الحي والتسليم

مشروع محفوظ → نشاط مؤكد → GPS أو دبوس → عنوان وخريطة → منشآت مشابهة → بحث مسموح → أدلة محفوظة → تفسير عربي موثق → عودة إلى المشروع.

- استخدام بيانات حقيقية مأذونة؛ بيانات الأعطال الاصطناعية تبقى في الاختبارات المعزولة فقط.
- استخدام مصادر مقبولة فعليًا، وليس كل الجهات الموجودة في مرجع الحصر.
- اختبار الفهرسة الخارجية في مساحة اختبار معزولة، دون تعديل المعرفة المشتركة.
- التفسير يستهلك الأدلة المعتمدة، ويبيّن النقص والمصادر؛ لا يصدر أرقامًا مالية أو قرار تمويل.
- تقديم سجل نتائج يميز نجاح الاتصال عن جودة المحتوى وعن نجاح الرحلة كاملة.

القبول النهائي: يستطيع المالك إكمال الرحلة، وفهم نتائجها وحدودها، ومعالجة النقص، دون كشف معلومات أو اختلاط بيانات. الدعوات تظل مغلقة.

## 5. إدارة التنفيذ والميزانية والموافقات

هذا القسم محدث بقرار المالك اللاحق: الميزانية تقريبية للقياس وليست حدًا يوقف المهمة، وينسخ اشتراط سقف توكنز ملزم في الصياغة السابقة.

- هدف واحد نشط لكل شريحة تنفيذية قصيرة، مع نتيجة قابلة للتحقق ونقطة توقف آمنة.
- تقدير استهلاك قبل الشريحة، دون token_budget آلي ما لم يطلب المالك لاحقًا حدًا صريحًا.
- لا استدعاء لعداد الاستهلاك بعد كل عملية، ولا توقف لمجرد تجاوز التقدير.
- تقرير واحد عند انتهاء الهدف: التغييرات، الأدلة، المتبقي، الاستهلاك الفعلي والزمن.
- عند توسع جوهري غير متوقع في النطاق أو الحاجة لصلاحية جديدة، يشرح الأثر وتطلب موافقة المالك قبل التوسع.
- الموافقات المنفصلة: دمج الطلبات، منح صلاحية إدارية إن كانت ناقصة، ترحيل بيانات المالك، Snapshot الخادم، والنشر أو التفعيل الخارجي.
- لا تُغلق المرحلة بسبب نفاد التقدير أو نجاح اختبارات جزئية؛ يبقى المتبقي مسجلًا صراحة.
