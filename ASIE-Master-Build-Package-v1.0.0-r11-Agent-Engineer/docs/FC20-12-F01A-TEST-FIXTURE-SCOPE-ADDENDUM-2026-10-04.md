الأثر المسموح في الملف:

2. استخدام دورة تحقق محلية اختبارية ومسار الكتابة الداخلي المتحقق الذي يقرره تنفيذ F01A، بدل تمرير الحالة والبصمة إلى الإنشاء العام.

4. إبقاء الاختبارات الأربعة السابقة واختبار غياب سياق معتمد حاليًا، وإثبات استمرار توقعاتها الأمنية.

لا تُضاف واجهة عميل، أو ملف لغة، أو schema، أو مكتبة، أو fixture إنتاجية إلى هذه التوسعة.

## 4. حد الكتابة الداخلي — اتجاه التنفيذ لا عقد جديد

الفصل المطلوب موجود في الخطة الأصلية: الإنشاء العام لمسودة خادمية، والنتيجة المحلية المتحققة لها مدخل داخلي منفصل.

التوقيع المرشح مفاهيميًا: دالة داخل Repository تستقبل نموذج `IntelligenceContext` متحققًا وPrincipal ومعطيات تتبع خادمية؛ اسمها وتوقيعها النهائيان يُحسمان بعد قراءة العقود القائمة. هذا ليس Route أو Socket أو عقد API جديدًا.

قبل كتابة أو إعادة استخدام نتيجة:
- تحقق الصلاحية وملكية المشروع ونطاق المؤسسة، قبل البناء وcache/replay.
- تحقق دورة النموذج وسلامة مادته وفق قواعد البصمة والإصدار القائمة؛ وجود كائن Python أو اسم دالة داخلية لا يجعل المحتوى موثوقًا.
- لا `trusted=true` أو `internal=true` في طلب العميل، ولا fallback إلى الإنشاء العام الخام.
- يبقى المثال محليًا معزولًا وغير موصول بتشغيل الإنتاج؛ لا يعيد قدرة HTTP المحجوبة ولا يحل محل AAS/Bus/Socket.

لا يغير الملحق نموذج السياق أو دلالات بصمته وإصداراته. إن احتاج تطبيق حد الكتابة تغيير عقد خارج allowlist، يلزم قرار آخر محدد لا استثناء ضمني.

- تجهيزات وطلبات مزود مصطنعة داخل الاختبارات المعزولة فقط؛ لا اتصال خارجي.

- الفحوص مرة واحدة على رأس التنفيذ النهائي وفق المخاطر والبوابات؛ لا تكرار اختبارات نجاح غير متأثرة.
